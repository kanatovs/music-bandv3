Kanatov Sabyrzhan and Zhaxylyk Alikhan

Objective: Continue the Cold Carti fan website with an interactive release collection, keyboard controls, a two-step form, sound and animations.

1. Covers, text and ratings

  1. Find the cover, title and rating controls with DOM selectors.
  2. Click a thumbnail to change the large image's src, alt, title and year.
  3. Click a star to set a rating and update its color and text.

Files: studio.html, studio.js, studio.css

2. Keyboard events and switch

  1. Listen for keydown while a navigation link has focus.
  2. Use switch to move focus with arrow keys, Home and End.
  3. Use another switch in filterByYear() to choose releases for a supported year.

Files: site.js, music-library.js

3. A two-step form and callback

  1. Keep the contact fields in two steps and validate before Next.
  2. Pass renderFormStep to goToStep() as a callback to show the chosen step.
  3. Keep field values when moving Back, and show a local result after the final check.
  4. Reject malformed email characters in both forms before allowing progress.

Files: contact.html, site.js, style.css

4. Objects, arrays and functions

  1. Store release objects in a catalogue array and manage selections through collection methods.
  2. Filter the array by year and search text using callback functions.
  3. Build the resulting cards with a for...of loop, then update the collection without reloading.

Files: music-library.js, studio.js, studio.html

5. A sound effect

  1. Connect the sound button to a short local WAV signal.
  2. Pause and restart one audio element so repeated clicks do not create overlapping players.
  3. Display playback feedback and handle a failed play() call.

Files: studio.html, studio.js, assets/audio/archive-chime.wav

6. Animation, structure and usability

  1. Animate a cover when it changes and highlight a newly added collection item.
  2. Keep HTML, CSS, data and behavior in separate files with named functions.
  3. Support small screens, visible keyboard focus and reduced-motion preferences.

Files: studio.html, studio.css, music-library.js, studio.js, site.js

Checks and reflection

  • JavaScript syntax checks and the static link checker passed.
  • 14 automated tests passed: 5 collection tests and 9 email validation tests.
  • Chromium: 30 layouts across six pages at 320, 390, 768, 992 and 1440 pixels; no horizontal overflow.
  • Checked gallery, ratings, year/search filters, add/remove, arrow navigation, form steps and reset.
  • The 0.42-second local sound played and ended; repeated clicks reused one player.
  • The reported comma-only email and similar malformed addresses were rejected in both forms.

Challenges and solutions

A form error can belong to a hidden step. Show that step before moving focus to its first invalid field.

Repeated sound clicks need to stay clear. Reuse one audio element, pause and restart it, and ignore feedback from older playback requests.

The shared script runs on several different pages. Check that a component exists before initializing its controls.

Reflection

The new features connect JavaScript data with visible controls. Keeping data, page structure and appearance in separate files makes the code easier to change. Forms are local demonstrations; collections and ratings are cleared on reload.
